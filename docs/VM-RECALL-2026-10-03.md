# Rappel contextualisé : mesures VM du 3 octobre 2026

Le commit `ecd83d1`, confirmé sur GitHub avant ce lot, sert de référence. L’outil
`tools.benchmark_contextual_recall` crée des corpus jetables de 300, 1000 et 3000
Informations, séparés pour journaux complets et reçus compactés. Il mesure huit
scénarios trois fois sur chaque corpus chaud. Le code métier n’est pas changé.

La VM Eidolon-Memory utilise Python 3.13.5 ; le tempfile est `/tmp`, **tmpfs**.
Les temps incluent les compteurs d’ouvertures de fichiers (Markdown canonique,
JSON historique, Markdown d’Events et dossiers), pas des lectures physiques.
La préparation et les contrôles/hash finaux sont exclus des temps de requête.
Les trois répétitions portent sur le même corpus chaud, pas trois corpus
indépendants ; chaque taille/historique a en revanche son propre corpus neuf.
La charge externe et les caches de l’hôte ne sont pas contrôlés.

## Réponses attendues vérifiées

Neuf Informations pertinentes déclarent explicitement les cas : confirmée et
applicable, non vérifiée, contexte absent, conflit déclaré, expirée, autre
contexte, réfutée, supplantée et suppression en attente. Les autres Informations
sont du bruit lexical synthétique. Ces annotations ne sont pas inférées du texte.

| Scénario | Réponse exigée |
| --- | --- |
| operational | Quatre sources courantes ; incertitude sur trois, exclusions expliquées |
| historical | Les neuf sources actuelles et leurs avertissements ; pas anciennes révisions |
| HIGH | Sources valide et conflictuelle de niveau HIGH ; conflit à revoir |
| project-current | Deux sources courantes liées, dossier CURRENT |
| project-historical | Les trois sources liées, dont expirée à revoir, dossier CURRENT |
| budget | Une source admissible et extrait limité à sept caractères, après filtrage |
| unknown-scope | Cinq sources, contexte UNKNOWN et revue requise ; pas universalité déduite |
| project-stale | Texte canonique corrigé/révision 2, dossier STALE sans reconstruction implicite |

Chaque réponse est comparée aux identités attendues, révisions, contenu, statut
épistémique, disponibilité, applicability, needs_review, provenance et vérification.
La comparaison d’empreintes avant/après requêtes vérifie que canonique, historique
et dossiers restent inchangés, hors verrous techniques. Une correction explicite
hors chronométrage crée la dernière situation STALE ; tous les objets attendus
et la readiness sont revérifiés ensuite. Le dossier n’est pas reconstruit par le
rappel. Les Threads de fixture sont créés directement, hors mesure ; cela ne
mesure pas le parcours métier de leur création.

## Reproduction

```sh
MEMORY_ENGINE_ROOT=/tmp/em-recall-unused PYTHONDONTWRITEBYTECODE=1 \
  .venv/bin/python -B -m tools.benchmark_contextual_recall \
  --sizes 300 1000 3000 --repeats 3 \
  --output /tmp/contextual-recall.json
```

Le précontrôle à neuf objets/une requête par scénario a réussi sur live/compact.
Une substitution en mémoire supprimant needs_review provoque une erreur du
vérificateur ; la mesure refuse ainsi de compter une réponse sémantiquement
fausse comme réussite. Les corpus sont supprimés automatiquement.

## Portée

Cette mesure vérifie des règles sur un corpus artificiel avec réponse connue.
Elle ne valide pas la pertinence sur langue utilisateur, la recherche sémantique,
un corpus réel/anonymisé, la latence de production, un tokenizer/modèle, la taille
finale du prompt ou les adaptateurs clients. Les budgets portent sur les extraits,
pas toute la metadata. Le mode historical consulte le canonique courant ; il ne
reconstitue pas le texte des révisions remplacées. Aucune coupure électrique ni
activation de services n’est acquise. Les estimations gelées restent inchangées.

## Résultats observés

Six corpus neufs, 144 requêtes mesurées ; 4300 objets vérifiés sur chaque
historique (300+1000+3000), tous les scénarios/révisions/review flags conformes,
readiness finale vraie. Empreintes avant/après requêtes identiques.

Le coût augmente avec le corpus bien que quatre sources seulement soient
rendues dans ce scénario. L’audit de readiness et la recherche lexicale gardent
leurs parcours complets. La sélection projet ajoute le contrôle de dossier et
ses lectures ; la compaction réduit la validation des snapshots sans supprimer
les lectures globales. Aucun seuil de latence de production n’est déclaré atteint.
