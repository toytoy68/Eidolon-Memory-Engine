# Audit du Memory Engine — 30 septembre 2026

## Périmètre et méthode

Audit du code de `refactor/architecture-v1` au commit `81bc8c4`, sans utiliser
`TODO-LIST.md` pour établir les constats ou l'estimation. Inspection des
modules `core/`, des CLI historiques `services/`, des tests d'intégration et
des contrats exposés. Exécution de la suite locale avec les cinq cas
multiprocessus exclus : **624 réussis, 5 non exécutés**. Ce résultat ne valide
ni le stockage réel, ni les services de la VM, ni Hermes ou Eidolon Core.

## Ce qui fonctionne dans le dépôt

| Domaine | Preuve dans le code | Limite observée |
| --- | --- | --- |
| Source de vérité fichier | `FilesystemBackend`, `ThreadStorage`, formats versionnés, révisions et verrous dans `core/persistence.py` | La sûreté suppose que tous les écrivains de la même racine utilisent les mêmes règles. |
| Thread, Event et Operation | Dépôts typés, création Thread liée et changement de statut journalisés ; tests d'interruption et de rejeu dans `tests/integration/` | `ThreadStorage.delete` et d'autres accès directs ne suivent pas ce parcours ; les Events d'écriture Information ne sont pas coordonnés de la même manière. |
| Suppression Information | Reçu `APPLYING_DELETE`, contrôle des liens, reprise explicite et tests d'interruption | Les reçus historiques ambigus réclament une décision humaine ; la reprise au démarrage n'est pas câblée. |
| Recherche et contexte | Recherche fichier, classement `lexical_v1`, filtres épistémiques, extraits bornés et évaluation par jugements | Classement encore lexical ; qualité des preuves, récence et pertinence réelle non mesurées sur corpus représentatif. |
| Migration | Inventaire, précontrôle et simulation sans écriture dans `core/migration/` | Aucun convertisseur validé des documents et journaux historiques ; les Reviews anciennes n'ont pas de dépôt core équivalent. |
| Index et clients | Manifeste et delta de fichiers dans `core/indexing/`; enveloppes de requêtes Thread | Aucun connecteur Qdrant ni synchronisation d'index ; pas d'API opérationnelle vers Eidolon Core. Le plugin Hermes est extérieur à ce dépôt et n'est pas validé ici. |
| Exploitation | CLI de reprise, audits en lecture seule, tableau de bord local avec authentification | Déploiement, restauration, données réelles et cinq tests de concurrence à vérifier sur la VM. Le tableau de bord n'est pas une interface métier. |

## Estimation

La cible évaluée est un **moteur autonome utilisable avec les données
historiques et des clients réels**, pas seulement une démonstration sur des
fixtures. Les poids représentent l'importance de chaque bloc pour cette cible ;
les pourcentages sont un jugement d'ingénierie, non un taux de lignes ou de
tests terminés.

| Bloc | Poids | Avancement estimé | Contribution |
| --- | ---: | ---: | ---: |
| Modèles, stockage et requêtes de base | 20 % | 85 % | 17 points |
| Écritures coordonnées, Events et reprise | 20 % | 65 % | 13 points |
| Recherche et contexte | 15 % | 50 % | 7,5 points |
| Migration des données anciennes | 15 % | 20 % | 3 points |
| Intégration clients/API et index éventuel | 15 % | 10 % | 1,5 point |
| Validation sur VM et exploitation | 10 % | 25 % | 2,5 points |
| Cycle de vie, consolidation et rétention | 5 % | 20 % | 1 point |
| **Total indicatif** | **100 %** | | **45,5 %** |

**Estimation globale : environ 45 % (plage raisonnable 35–55 %).** Le noyau
sur données isolées est plus avancé, autour de **70 %** pour une preuve de
concept. Une mise en service avec les données existantes est moins avancée :
la migration, la coexistence des écrivains et la validation de reprise sur la
VM sont des jalons bloquants. Les nombres changeront si le périmètre évolue ;
Qdrant reste optionnel tant qu'un besoin mesuré ne le justifie pas.

## Ordre recommandé

1. Sur une copie arrêtée de la VM : inventaire des écrivains et formats,
   sauvegarde avec restauration vérifiée, puis les cinq tests de concurrence.
2. Trancher le format cible et la conservation des Events/Reviews historiques ;
   construire une migration explicite et réexécutable avec rapports de rejets.
3. Faire passer les écritures métier Information et Thread par des chemins
   coordonnés, puis répéter les tests d'interruption sur des données anonymisées.
4. Définir un petit contrat de lecture/écriture avec Eidolon Core et valider
   Hermes dans sa vraie installation ; mesurer la recherche avant d'ajouter un
   index dérivé.

La suite verte atteste les scénarios simulés. Elle n'autorise pas à démarrer les
nouveaux écrivains sur les fichiers historiques sans ces étapes.
