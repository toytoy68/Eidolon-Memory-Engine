Une assertion du troisième test comparait la fin de l'écrivain à un timestamp
pris par l'autre thread après le retour de rebuild. Or l'écrivain peut finir
légitimement après libération du verrou mais avant le réveil de l'appelant.
Un délai de 50 ms à cet endroit reproduit un échec sur le code correct. La sonde
vérifie désormais l'absence de fin d'écriture pendant les embeddings, avec un
signal indiquant la tentative de l'écrivain, puis vérifie sa fin et les révisions
respectives canon/index. Le délai après retour reste présent pour couvrir cet
ordonnancement valide. Le mutant sans verrou reste détecté.

Compromis confirmé : rebuild tient le verrou canonique pendant toute la
reconstruction, embeddings compris. Les écrivains coopératifs attendent ; aucune
promesse de faible latence sur gros corpus n'est déduite de ces tests.

C181 ajoute aussi cinq tests Core de jeton (propriétaires, bornes, liens). Ils sont
intégrés sans modification. Ici 13 tests de jeton passent, deux changements de
propriétaire échouent avec EINVAL dans le conteneur malgré uid 0 ; ce n'est pas une
validation des contrôles concernés. Une étape CI Core dédiée exécute les cinq
sondes en root avec de vrais changements d'UID sur fichiers synthétiques. Résultat confirmé ensuite dans la CI Core : les cinq sondes passent avec -W error (0,11 s), y compris les deux propriétaires. Aucune permission de secret réel modifiée.
